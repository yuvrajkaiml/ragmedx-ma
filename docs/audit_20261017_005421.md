## A. Pipeline Data Flow & Provenance Audit

### A.1 Canonical Pipeline Flow

```
User Query
  ↓
[Agent 1: QueryUnderstandingAgent]
  Outputs: processed_query {medical_specialty, intent, expanded_query, abbreviations, confidence}
  Provenance carried: none — no document IDs yet
  ↓
[Agent 2: IterativeRetrievalAgent (MGA)] ← loops with retrieval_provider
  Calls retrieval_provider(query, optimized_query)
  Retrieval provider = RAGPipeline.retrieve_evidence()
    → BGEEmbedding → FAISSVectorStore → DenseRetriever
    → SparseRetriever (BM25) → HybridRetriever (RRF)
    → CrossEncoderReranker
    → CitationGenerator → evidence dicts
  Evidence dict schema:
    chunk_id, document_id, source_type, title, cited_text,
    cross_encoder_logit, relevance_score, cross_encoder_score,
    evidence_quality_score, citation_marker, journal,
    publication_year, doi, url
  Provenance carried: chunk_id ✅, document_id ✅, citation_marker ✅
  iteration number tracked in orchestrator_iteration ✅
  index_id: NOT in evidence dict — only present in index file path ⚠️
  ↓
[Agent 3: EvidenceRerankingAgent]
  Input: evidence list (with chunk_id, citation_marker)
  Adds: evidence_grade, grade_weight, reranking_score
  May FILTER evidence via selected_markers from LLM
  Provenance carried: citation_marker (may be translated) ✅
  chunk_id preserved IF item survives filter ✅
  document_id preserved IF item survives filter ✅
  LOSS RISK: LLM may select markers not in canonical set → _resolve_selected_markers()
    handles [EX] → [Doc X] translation but only by ordinal ⚠️
  ↓
[Agent 4: GeneratorAgent]
  Input: evidence list + question
  Output: answer text with [citation_marker] inline + answer_citations list
  Provenance: LLM embeds citation markers directly in text
  Validation: _extract_valid_citations checks markers against evidence set ✅
  LOSS: if LLM hallucinates a citation outside the evidence set, it raises ValueError ✅
  BUT: no chunk_id or document_id appears in final answer text — only citation marker ⚠️
  ↓
[Agent 5: CriticAgent]
  Input: answer + evidence + question
  Adds: evidence_verification dict {referenced_markers, mapped_markers, unresolved_markers}
  _verify_claim_citations: checks answer markers resolve to evidence spans ✅
  EvidenceVerifier: structural check on MedicalChunk fields ✅
  LOSS: verdict.evidence_verification is stored in critic_verdict only — not propagated to final response ⚠️
  ↓
[Agent 6: ConfidenceCalibrationAgent]
  Input: evidence list + critic_verdict
  Uses: relevance_score, cross_encoder_score, evidence_quality_score (from retrieval)
  Uses: factual_consistency, citation_support, hallucination_risk (from critic)
  No new document IDs introduced or lost
  ISSUE: requires critic_verdict — if disable_critic=True, orchestrator bypasses agent
    and sets synthetic calibration values (1.0 for everything) ⚠️
  ↓
[Agent 7: AbstentionDecisionAgent]
  Input: confidence_calibration + pipeline flags
  Output: decision (PROCEED/ABSTAIN) + reasons
  Provenance: no document IDs used here
  ↓
[ResponseBuilder.build_medical_response]
  Translates AgentState → VerifiedAnswerResponse / AbstentionResponse / ErrorResponse
  CitationOutput built from evidence list (document_id, title, cited_text, relevance_score)
  NOTE: evidence_verification from CriticAgent NOT included in public response ⚠️
```

| NLI contradiction | ❌ | assessed by LLM only | ❌ | ❌ | ❌ | ✅ flag | ❌ |

**Summary of provenance losses:**
1. `index_id` (which FAISS index served this query) is never embedded in evidence dicts. Only captured in run_metadata of benchmark outputs.
2. `retrieval_iteration` (which iteration fetched each evidence item) is tracked in `retrieval_iterations` list in AgentState but not in individual evidence items — impossible to trace which iteration contributed a specific chunk.
3. `evidence_grade`, `reranking_score` are added by the reranker but not propagated to the final API response.
4. `evidence_verification` (unresolved/invalid markers from CriticAgent) is stored in `critic_verdict` inside AgentState but not surfaced in the public response schema.
5. `cross_encoder_logit` (raw score before sigmoid) is stored in evidence dict during retrieval but NOT in AgentState's evidence schema fields — it is only informational metadata at the pipeline boundary.

### C.2 Metric Direction Issues Found

1. **ROUGE-L as primary "accuracy" metric on BioASQ free-text answers** — ROUGE-L F1 is an appropriate proxy for generative QA tasks where the reference is a free-text ideal answer (BioASQ `ideal_answer`). However, BioASQ also contains yes/no questions (`type: yesno`) and factoid questions (`type: factoid`) for which ROUGE-L against the ideal answer is a poor discriminator. No per-type breakdown exists in the result files. The `accuracy` field in results is aliased to `rouge_l_f1` (see `metrics.py`). The old `compute_accuracy` was a bidirectional substring check with a known bug (empty string matched any reference). The bug was fixed in the current code but existing results may contain outputs computed with the old function.

2. **`compute_accuracy` bug — historical** — `compute_accuracy` in the original code used `"" in truth` which returned `True` for every abstention. The ablation summary states abstention rate for full-pipeline was 56.7%. If those abstentions were scored as "correct" by the old function, historic `accuracy` numbers from earlier runs (pilot25) would be inflated. The current code (`compute_exact_containment_rate`) fixes this — any value labelled `accuracy` in the 6 n30 results uses `rouge_l_f1` as the alias. The pilot25 results (`step4_full-pipeline_pilot25_*`) may contain the old broken metric. **Evidence tier: SOFTWARE INSPECTION.**

3. **Abstention counted with denominator = ALL samples** — ROUGE-L F1 is computed over all 30 samples including abstentions (which score 0). The ablation summary already documents this and provides a "non-abstained" ROUGE-L column. This is the correct methodology (abstentions penalize the overall score) but the full-pipeline's ROUGE-L advantage disappears when abstentions are excluded (0.2049 vs 0.1996 for no-critic). No statistical significance testing has been performed; n=30 is too small for reliable conclusions.

4. **Citation support rate denominator** — `compute_citation_support_rate` counts citations over ALL responses including abstentions. `compute_answer_with_citation_rate` correctly excludes abstentions. Both are reported but the ablation summary's "Citation Support Rate" uses the non-abstained denominator while the stored `citation_support_rate` in metrics JSON uses all responses. This creates a labelling inconsistency between the result JSON and the ablation summary table.

5. **No Precision@K, Recall@K, MRR, nDCG, ECE, Brier score, or risk-coverage in any result file** — these metrics exist as functions in `evaluation/metrics.py` but are never called in the benchmark runners (`mirage_runner.py`, `run_step4_matrix.py`). They are NOT MEASURED in any existing result.

6. **Retrieval coverage uses keyword overlap, not ground-truth document IDs** — `compute_retrieval_coverage` in `mirage_runner.py` measures whether any retrieved passage contains a word from the reference answer. This is an extremely weak retrieval quality signal and does not measure whether the correct source documents were retrieved. It returns 1.0 for full-pipeline but this is vacuously easy to satisfy (3 chunks × any word from a multi-word answer). **NOT MEASURED at appropriate granularity.**

7. **Prior mock-mode leakage** — the `run_evaluation()` method in `mirage_runner.py` accepts `use_mock_fallback=True` as the LLM default; results labelled `"COMPLETED_MOCK_SCAFFOLD"` are explicitly not real benchmark results. The 6 n30 result files are labelled `"COMPLETED_RAG_EVALUATION"` with `llm_mode=local`, so they are NOT mock results. Earlier pilot25 results also show `llm_mode=local`. **No mock leakage found in the 6 canonical n30 result files.**

8. **`plain-llm-no-rag` rouge_l_f1 (0.1575) higher than full-pipeline (0.0888)** — This is real and explainable: the full-pipeline abstains 56.7% of the time (17/30 questions score 0 for ROUGE-L), dragging the mean down. The non-abstained ROUGE-L (0.2049) is higher than plain-LLM (0.1575), which is the correct comparison for per-answer quality. This is not a metric inversion; it is correctly described in the ablation summary.

### C.3 Known Sildenafil/Prolia Regression

The ablation summary documents a hallucination: the reranking agent attributed "trade name of sildenafil as Prolia" to a cited document. This is a citation faithfulness failure — the model invented an attribution. The full-pipeline correctly abstained on this question; no-calibration and no-critic produced a wrong answer with a hallucinated citation. This regression has no automated test coverage and is documented only in the ablation narrative.
