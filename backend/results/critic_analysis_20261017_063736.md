## Critical Data Limitation

| `question` | yes |
| `true_answer` | yes |
| `predicted_answer` (final) | yes |

## Caveats

1. CRITICAL LIMITATION: The n30 ablation result files do not record draft_answer, critic_verdict, or critic_reviews. Per-question critic accept/reject/rewrite counts are therefore NOT MEASURED. What data would be needed: IncrementalResultWriter must be extended to save draft_answer (pre-critic), critic_verdict dict, and critic_round_count per sample.

2. ROUGE-L of draft vs final is NOT MEASURED for the same reason. Even if it were measured, ROUGE-L change != correctness change. A rewrite can lower ROUGE-L (more concise) while being more factually correct, or raise ROUGE-L (more verbose) while still being wrong. ROUGE-L is a surface-similarity metric, not a safety or correctness metric.

3. Cross-config abstention delta (full-pipeline vs no-critic) is a population-level inference with n=30. It does NOT isolate critic effect from calibration, retrieval variance, or generation variance. With n=30 the delta is not statistically reliable. A McNemar test cannot be applied because per-question critic decision data is absent.

4. Evidence tier for abstention counts: SOFTWARE TEST (direct file parsing). Evidence tier for cross-config delta inference: SOFTWARE TEST (arithmetic on parsed counts — no model judgment involved). No AUTOMATED MODEL JUDGE tier evidence was generated in this analysis because the critic verdict data needed for that tier is absent.

5. The no-critic config ran with disable_critic=True (inferred from config name and abstention rate difference). The no-calibration config ran with disable_calibration=True. These flags were set in run_step4_matrix.py but are not explicitly recorded in the output JSON run_metadata.
