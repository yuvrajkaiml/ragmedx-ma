## Identified Bottlenecks

Based on the mock profile (mock LLM calls are near-instant):

1. **LangGraph graph execution overhead** — `ainvoke`, state serialization (`model_dump`, `model_validate`), and Pydantic validation appear in the top functions. In a real GPU run, these are dwarfed by LLM generation time.

2. **State serialization** — `model_dump()` and `model_validate()` are called at every LangGraph node boundary. For n=30 questions, this accumulates.

3. **Evidence normalization** — `_normalize_and_validate_evidence` iterates over all evidence items; at high k values or many retrieval iterations, this grows linearly.

4. **On real GPU runs** (not reflected here): generation, critic, and query-understanding are all LLM calls and will dominate total latency (observed avg ~140s/question in full-pipeline n30 results).

---

## Recommended Optimisations

_These are RECOMMENDATIONS only; none are implemented here._

1. **RECOMMENDATION: Add QueryCache (Phase 4b)** — cache full pipeline results keyed by query + index_identity + retrieval_config + model_version. Cache hit avoids all LLM calls. Estimated saving: ~100% of generation time on repeated queries.

2. **RECOMMENDATION: Batch evidence reranking** — if k > 5, batch cross-encoder calls instead of iterating one-by-one. Cross-encoder is CPU-bound and benefits from batching.

3. **RECOMMENDATION: Skip gap analysis on first-pass if retrieval returns ≥ k items** — the first gap analysis call is often 'sufficient=True'; making this conditional saves one LLM call per question.

4. **RECOMMENDATION: Pre-warm LangGraph graph** — `workflow.compile()` is called once per orchestrator instance; ensure the orchestrator is a long-lived singleton, not re-created per request.

5. **RECOMMENDATION: Reduce model_dump / model_validate round-trips** — the LangGraph node boundary serializes AgentState at every step. A future version could pass the AgentState object directly when moving to a single-process async executor.
